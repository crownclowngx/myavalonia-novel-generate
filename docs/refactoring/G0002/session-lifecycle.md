# G0002 会话与关闭生命周期

## 编辑到保存

Document 接受输入并构造不可变快照 → ProjectSession 提升编辑版本 → 容量为 1 的通知队列合并请求 →
450 ms 延迟后保存最新快照。快照本身始终保留在会话，不会因通知合并而丢失。手动保存使用同一 SemaphoreSlim
串行入口，不能与自动保存交叉覆盖；保存期间的新输入形成后续版本。

状态为已保存、有未保存修改、正在保存、保存失败；保存失败另区分当前编辑是否已有可验证的恢复副本。
数据库版本与编辑版本分开：前者检测外部变化，后者判断异步保存的结果是否仍覆盖全部当前输入。
必要磁盘保存不接收网络/窗口取消令牌；关闭取消不会直接抹掉已接受的编辑。

## 两段关闭

1. PrepareCloseAsync 串行冻结新编辑，保存最新快照，或验证该编辑版本已完整写入恢复副本。
2. 准备失败：解除冻结，保存队列继续存活，作者可继续编辑和重试。
3. 准备成功：保存该版本的落盘证明；最终释放不再重复写入。
4. DisposeAsync 完成队列并排空工作任务，然后释放文件租约、移除根服务登记。
5. 根服务退出时处理仍登记的会话；每个异常被观察，不把失败当作成功。

Standalone 在释放 DI Scope 之前执行关闭准备；两种保存均失败时保留原控件与 Scope。成功后先释放文档 Scope，
再释放根容器，最后关闭窗口。业务操作与初始化都可等待，没有同步阻塞或未观察的 async void 业务任务。

真实 Host 没有相同的公开关闭否决接口。插件会在 Document/根服务释放时尝试保存与恢复；如果所有可写位置都失败，
异常与内存保留只能在当前进程存在，不能承诺进程强退后仍可恢复。此限制需要 G0007/G0015 的真实 Host 联调记录。

## UI 线程与跨书隔离

状态事件通过初始化时捕获的 SynchronizationContext 回到界面，读当前状态而非应用迟到的旧结果。
切书前要求当前书保存成功，打开失败保留当前工作区。成功切换时显式加载新章节字段，即使两个选择项的 ID/标签相等，
也不能沿用上本书正文。已取消的文件选择结果不能提交给关闭中的 Document。
