# 分层规划与章纲契约

## 作者操作

填写创意、绑定本书连接，在“分层规划与近期章纲”选择 3–5 章及自动/协作模式。
模型形成全书主线、分卷目标、近期目标/冲突/视角/时地/事件/计划状态变化/伏笔/承接，以及必要实体建议。
没有模板材料也可开始；已有写作方法则每章至少落实一条原文到铺设、阻碍、兑现事件。
章纲锁定只禁止模型覆盖，作者仍可编辑。编辑自动保存草案，点击保存章纲才追加明确修订并生成 ReadyStamp。

## 采用不变量

- 同书、同起始章、同源快照；来源摘要使用属性排序的规范 JSON，重开不因字典顺序误判。
- 提案 1–3 个局部卷、3–5 章，每卷有章、卷序不倒退；不能移动已有章节的卷归属。
- 已有正文和摘要不被规划覆盖，已有卷章不删除，已有实体身份不重建。
- 主线、方法和必要字段合法；方法出处是本书原文的逐字片段，不宣称模型已证明文学效果。
- 已接受修订或锁定章禁止模型重规划；自动和协作共用同一门禁。
- 工作稿/正式稿和已发生事实不因规划而改变；StateChanges 明确是未来计划。
- 规划历史只追加，作品保存与会话更新都拒绝删除/覆盖旧记录；副本重映射身份。

## 失败与恢复

取消令牌在收到结果后、写入 Pending 前再次检查；网络取消仍可能计费，模型请求账本保留完整或部分结果。
候选先进入作品保存链路，采用失败仍可查看；保存与恢复同时失败时明确显示只在内存，不显示成功。
采用后若仅恢复副本成功，提示修复存储后保存。协作 Pending 随库重开，来源变化后拒绝旧候选。
主线、规范、卷目标、章纲等改变会使 ReadyStamp 失效，作者重新保存有效章纲后才能生成正文。

## 容量与边界

一条请求预算上限 250000 token（包含保守预留），不自动重试。账本使用实际用量或保守未知预留，输入 UTF-8 预算不冒充 tokenizer。
最多 2000 条规划修订，每条记录当时卷章规划；大规模长篇压测与归档属于 G0019。
没有开放完整规划历史回滚 UI；可以查看最近记录并手工修改后保存新版本。完整正文生成与检查属于 G0011。
