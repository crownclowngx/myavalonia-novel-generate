# 容量与局部拆分协议

## 三个数字各管什么

| 设置 | 含义 |
| --- | --- |
| 全过程 token / 请求上限 | 原运行、修订、失败、纠正和子单元共享的累计额度，不会自动扩大。 |
| 单次输出上限 | 本阶段一次响应的输出预留；不是期望模型写满的长度。 |
| 单次上下文容量 | 输入保守估算加输出预留的容量边界；设置不能扩大服务商窗口。 |

输入估算为 system + user + JSON Schema 的 UTF-8 字节数，再加 16384 适配余量；这是保守估算而非精确 tokenizer 或实际费用。已有已知用量仍按实测记账，缺失用量保留原预留。

DeepSeek Flash/V4 已知窗口按 1000000 token 检查；手工值只能收紧已知窗口。其他模型需显式填写才检查远端窗口，本地提示总字符 250000 防护始终生效。界面 0 表示自动识别，显式值为 8192–2000000。

## 拆分与恢复

1. 只允许尚未进入跨章整合的提取节点拆分。整合和报告已有自己的有界分层计划，不套用原文二分。
2. 输入预检失败先拆分，父节点不发送也不记费。输出必须是明确长度截断且输入、输出用量均已知，才可以自动拆分。
3. 单个父节点替换为两个新节点，章节和原文坐标保持连续覆盖；正文没有遗漏或重复。上下文可以重叠，只用于理解。
4. 默认最多 3 层，允许 0–8；0 关闭自动拆分。每个子正文至少 200 字符，服务选项可设 200–6000。
5. 先检查全部剩余提取请求数、两个直接子节点的 token 预留及后续报告额度；后续节点发送前继续逐次检查。不会把预测当作整本总成本保证。
6. 有其他未复核失败或未知用量时停止，不顺带确认费用。深度、大小或预算不满足也停止并保留候选。
7. 父操作 ID、区间、原因、深度及两份子区间追加到拆分历史；新切分与节点在同一运行事务保存。成功节点及原失败成本不删除。
8. 账本复核后、运行事务提交前发生磁盘失败，重开从原父记录重建子单元，不重发父请求。“继续运行”在未追加新约束且启用拆分时也保留已知截断父操作 ID。暂停重开沿用已保存子队列。

每个节点最多一次格式纠正，与拆分次数分别持久化；未知费用、取消、断流、超时均不按完整格式错误自动重试。旧记录缺少完整性信息时不能自动推定完整。

## 流与数据版本

SSE 单行/事件最多 262144 字符，正文最多 1000000 字符；累计封装上限为 min(128×1024×1024, max(8000000, 输出上限×1024+65536)) 字符。计数包括推理事件及封装；超时仍有界。本地 StreamLimit 与远端 OutputLimit 分别诊断，增加全过程预算不能解除这两种限制。

schema3 首次打开 schema1/2 运行库前在工作区 Backups 建立 SQLite 一致性快照，包含已提交 WAL 数据；失败则不升级。回退旧插件应先退出宿主，再恢复匹配的库备份。正式用户库本次未打开写入，升级仅在离线副本验证。
