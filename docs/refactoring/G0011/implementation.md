# G0011 实施方案

日期：2026-09-12。基线 `a5fa71a`（184 项测试）。

## 设计思路与职责

`ChapterGenerationService` 编排生成、审校、有限修正，依赖连接服务、统一请求入口与候选存储端口；不依赖窗口或作品会话。
`ChapterGenerationRules` 执行无 I/O 门禁、证据核对、字数容差、局部替换和提交变换；`ChapterWorkStore` 使用独立 SQLite 保存过程结果。
`MainDocument.Generation` 负责候选显示、取消、恢复选择、证据定位与主动提交。一个普通服务与明确阶段循环即可表达有限流程，未引入通用工作流框架。

生成与审校预设在开始前冻结；每次远程调用仍核对连接版本。字数采用 Unicode 非空白字符，范围 100–10000、容差 ±20%，与 token 预算分开。
四维审校（规则/事实/剧情方法/文风）都必须完成；本地硬规则与事实证据可以否决模型的通过结论。
事实仅引用已有书内实体与连续正文证据，计划/歧义不得进入已发生事实。背景用品不强制登记；影响后续身份/状态的一致性问题必须处理。

## 修正与恢复

允许 0–2 次局部修正，每次 1–10 个唯一原文替换，累计最多正文 30%；匹配从首个命中的下一字符检查重叠歧义。
每次修改后重新审校全部四维并检查本地规则、字数、锁定状态和事实，不沿用旧文本的事实元数据。
审校/修正 JSON 仅修复 BOM、外围空白和完整代码围栏；原始响应保留在请求账本，不补造缺失字段或截断内容。

每次候选更新递增序列；数据库原子拒绝旧序列与不同任务身份覆盖。候选流与作者编辑框完全分开，显示异常不会影响候选落盘。
异步 UI 回调通过视图代次和候选序列拒绝迟到状态。取消在远程返回后再次检查，已有结果可恢复但不提交。

## 原子提交

`ProjectSession` 的统一事务入口可同时保存生成正文、摘要、不可变修订与事实指针；失败不修改内存/数据库稿件。
提交前重新核对来源指纹、原编辑正文、当前规范、前文稿件和事实证据。后续已有工作稿、跳章或前文未检查/未提交编辑时阻止自动续写。
磁盘保存期间的较新编辑按正文和摘要字段合并：无关书名编辑不会把生成正文换回旧正文，真正的新正文输入优先。
状态订阅异常逐个隔离，不能终止自动保存或阻断租约释放。正式稿只由作者主动定稿。
