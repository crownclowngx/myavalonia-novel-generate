# 单章生成与提交契约

## 使用路径

保存有效章纲 → 设置字数与最多修正次数 → 生成并审校本章 → 查看独立候选、报告和问题证据 → 提交通过的候选为工作稿。
没有有效规划、连接或连续前文时，在发送请求前停止。手工未检查工作稿可保留，但不能作为自动续写的依据。
候选不自动覆盖编辑框；可随时取消远程请求。正式稿仍需作者明确点击定稿。

## 状态和数据

候选有 Drafting、Reviewing、Repairing、Ready、NeedsAttention、Cancelled、Failed；报告显示中文含义。
进程退出时停留在进行中的候选只有恢复记录，重开不会自动调用模型，点击恢复候选可查看；运行级中断/继续由 G0012 实现。
每次审校保存当时正文与报告，最多三份，最终正文、已验证事实、原编辑哈希、上下文指纹、运行与操作身份独立记录。
工作稿提交以候选操作身份去重，重复提交不能制造第二条修订或替换内容。

候选库 `chapter-work.db` 是本机恢复数据，不属于 `.noveldb` 导出备份；成功提交后的正文、摘要与事实已全部进入作品库。
更换机器应先提交需要保留的候选或人工另存正文。候选存储版本为 1；未知版本拒绝读写，不能静默重建覆盖。

## 门禁

四个检查维度都完成、锁定章纲保持、字数在容差内、无本地硬失败、无未决事实冲突，才可为 Ready。
模型的通过不是文学质量证明；本地事实键、旧值、书内实体、连续证据、时间状态和锁定字段必须再次验证。
来源变化使候选过期，不能先替换编辑稿再尝试提交。提交失败仍保留原稿与候选；重试不重新调用模型。

一个单章最多 2 + 2×修正次数条请求，共用 500000 token 上限及保守预留；不会暗中重发网络失败请求。
耗尽次数、用量、结构化报告无效或不确定结果时保留候选并停止。外围 JSON 格式修正完全本地进行，不额外收费。
软建议默认记录，不逐条阻塞；硬失败与未决事实不能被忽略。连续运行策略属于 G0012。
