# G0008 实施方案

关联 [阶段计划](plan.md)、[协议能力](model-protocol-and-capabilities.md)、[请求用量契约](request-usage-contract.md)。

## 职责划分

`ModelRequestService` 是生成、分析和检测的统一入口，负责校验、预算预留、超时、片段保存与最终状态。
`ITextModel` 只负责一次文本请求；`TextModelRouter` 显式选择 Codex/DeepSeek，并在发送前复核冻结连接。
`ModelRequestStore` 管理独立 SQLite 账本事务。具体任务通过 `IModelOutputContract` 校验自己的结构化结果。
业务服务不依赖 HTTP、进程或 ViewModel；协议适配器不取得作品仓库。使用接口与普通组合，不引入代理框架或反射注册。

## 连接面板

保存连接后可主动点击“生成一句检测（消耗额度）”，使用检查预设生成不超过 30 字的样本。
启动、选择连接和刷新凭据不会发起生成。检测期间可取消，关闭准备也会取消并等待账本收尾。
本连接最近 20 条请求可重开查看，包括未确认完成的请求与部分候选；它们不会自动成为工作稿。
新连接仍需明确填写 CLI exe 路径或 HTTPS 端点，作品仍需明确绑定连接版本。

## 关键处理

- HTTP 单请求 Authorization，禁用自动重定向与 Cookie，空闲或失败不自动改选另一连接。
- Codex 通过 `ProcessStartInfo.ArgumentList` 启动，无 shell、无可见窗口；仅 stdin 传提示词。并发排空 stderr，取消和解析失败终止本次进程树并等待退出。
- Codex 工作目录为单请求随机临时目录，结束后清理；不读取/复制认证文件，忽略个人配置，移除继承的 API Key 环境变量。
- SSE 先限制行/事件和总输入，再解析 JSON；内容与推理分离。持久化片段在 UI 通知之前，显示失败不改写执行终态。
- 不确定、截断、拒绝或未确认结束的请求阻止同预算继续发送；手动检测每次建立显式新预算，不假装自动续传。
- 本阶段不迁移作品 schema；请求账本独立 schema 1，不随作品备份/导出携带。
