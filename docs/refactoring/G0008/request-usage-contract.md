# 请求、用量与候选恢复契约

关联 [实现方案](implementation.md) 与 [模型能力](model-protocol-and-capabilities.md)。

## 生命周期与持久化

生成、检测和分析必须经 `ModelRequestService`，不能由 ViewModel 直接调用适配器。
每次请求有独立 OperationId、BudgetId、BookId 和冻结的连接 ID/版本/任务预设。账本位于本机数据目录 `model-requests.db`，
保存用量、状态和有界候选，不保存提示词、推理、Key、原始 HTTP 错误或 stderr。

1. 校验请求、任务契约与本地容量；取消的未开始请求不发送。
2. 同一 SQLite 写事务中核对预算上限、已发生消耗与未完成项，插入 Reserved。重复 OperationId 被唯一键拒绝。
3. 适配器报告累计正文，先写 Running 与候选，后通知 UI。SSE 通知最多约每 150ms 一次，正常结束或解析失败时刷新最后片段。
4. 成功且结构合格保存 Completed；服务商长度结束或本地软目标超限保存 Truncated。
5. 认证/余额/限流保存 Rejected；断流、取消、超时和其他不确定失败保存 Uncertain。失败不自动重发。

应用中断后 Reserved/Running 保留“未确认结束”，不能推断没有计费或重发。连接面板提供最近 20 条记录；
后续 G0012 再关联完整运行恢复。候选只是恢复材料，不等于已经接受的工作稿，更不能进入正式记忆。
最终状态写入失败时保留此前预留/片段并提示存储问题；不能把请求记为成功。

## 预算口径

每次预留为提示词及 Schema 的 UTF-8 字节数，加输出预设及 16384 tokens 固定余量。
这是保守规划量，不是 tokenizer 结果；Codex 自带上下文、推理及远端消耗存在额外不确定性。
已知输入/输出都存在时，账本按实际总数占用；任一缺失则继续占用预留，绝不写零。
实际用量超过预留仍如实记录，后续预算检查据此阻止继续；预留不是服务商硬计费封顶。

预算 ID 建立后上限不能在请求中扩大。请求数最多 1000；预留、运行中、不确定、拒绝或截断项阻止同预算继续。
本阶段自动重试次数为 **0**（有限重试的保守策略）；需复核后明确启动新操作/运行，不能静默换连接、无限重试或覆盖候选。
默认超时 5 分钟，可指定 0–15 分钟范围内正值；取消会关闭 HTTP 或终止并回收本次 CLI 进程树。

## 容量与结构

提示词加 Schema 至多 25 万字符；JSON 深度至多 32。SSE 单行/事件 262144 字符，总输入 800 万字符；
Codex 单 JSONL 行 200 万字符，总输入同为 800 万；账本正文至多 100 万字符。
不接受多 choice、工具返回、空完整正文、缺结束标志或负用量。结构结果拒绝空对象、重复字段，具体任务继续验证字段类型和取值范围。
输入达到协议容量导致尚不能完整解析的事件不保证恢复其内部正文；此前已解析片段仍保留。

## 本地门禁

协议矩阵覆盖跨中文 UTF-8 字节块、空块、推理隔离、截断、断流、非法 JSON、认证、余额、限流、连接隔离、未知用量、
预算原子预留/扩额/重复请求、重启保留、超时取消、进程 stderr 排空与退出，以及 Schema 预留、显示异常、超限候选回归。
自动化不需要真实密钥或模型请求。没有 AIFLOW、Windows CI 或发布门禁。
