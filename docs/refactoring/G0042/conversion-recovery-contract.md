# 报告转模板的预算与恢复契约

日期：2026-09-13。

## 正常顺序

保存冻结转换任务 → 保存在途操作 ID/输入指纹 → 账本预留 → 模型响应及实际/未知费用 → 本地契约校验 → 子步骤保存 → 有界合并 → 最终候选保存。模板库交付不属于模型请求事务。

## 恢复决策

| 现状 | 恢复行为 |
| --- | --- |
| 操作有完整且费用已知的响应 | 校验冻结契约，直接补保存；不发第二次请求 |
| 已保存成功子步骤 | 原样复用，输入/输出身份不可改写 |
| 响应完整、费用已知、格式或引用失败 | 最多一次定向纠正，旧费用保留；再次失败停下 |
| 截断、断流、未知费用 | 展示候选与费用，等待明确复核；再次打开不会自动发送 |
| 检查点失败、恢复文件成功 | 先恢复连续版本，再继续或交付候选 |
| 检查点和恢复文件都失败 | 报告未保存，不继续；已有请求账本仍可提供有限恢复 |
| 配置变化、指纹或账本身份不匹配 | 停止，不能将另一来源/请求当成本次结果 |
| 用户取消 | 取消网络并保留成功结果，下一次继续仍核对未决费用 |

同一预算的其他未知费用不会被一次自动格式纠正顺带确认。显式复核只说明允许在保守计费下继续，不把未知用量变成零或伪造准确价格。

恢复采用新操作 ID 仅发生在明确重试或一次已知格式纠正；预算不拆分以规避原成本。远端请求仍不承诺恰好一次，本地未发出的请求不计为真实调用。

## 容量边界

若整份材料可容纳则一次请求，否则按所选字段分组并二叉合并，最多 64 步。每个合并只接两个候选且重新预检实际长度；仍超容量时明确暂停，不能截断资料后宣称完整。改变单次容量或模型参数需新建转换，已有候选不覆盖。多步骤的成功片段保留，可针对问题步骤继续。
