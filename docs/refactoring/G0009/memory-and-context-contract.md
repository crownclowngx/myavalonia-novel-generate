# 故事记忆与上下文契约 v1

## 状态来源

第 N 章只能查询章序在 N 之前的有效修订。正式视图只用 FormalId；工作视图优先当前运行 WorkingId，再用 FormalId。
工作稿必须属于活动运行，前文指针与其 ContextStamp 一致。丢弃/回退只调整指针，查询自动排除失效内容，历史正文仍保留。
当前编辑稿、未接受候选、未来章正文和其他作品数据不作为已经发生的事实。

作者设定和当前章纲可以进入请求，但明确标注为设定/计划，不能充当剧情证据。
事实类别包括状态、关系、事件、物品归属、基础知情、伏笔；人物、地点、物品和组织都是书内实体。
关系与归属必须引用已登记的关联实体 ID，事实键包含关联 ID，不会让同字段的另一关系覆盖原关系，改名不破坏引用。普通值仍是短文本，尚未实现复杂关系图推理。

## 候选门禁

候选带作品、章节、实体、关联实体、类别、字段、预期旧值、新值、证据、时间状态、上下文与正文哈希。
只有明确标记 Established 的候选可以进入验证；Planned/Uncertain 拒绝。证据必须是本次生成正文的原文片段。
验证继续检查身份、来源指纹、旧值、字段边界和锁定状态。

验证成功后仍不是工作稿。FactDelta 携带规范指纹、正文哈希和运行身份，工作稿提交和作者定稿时再次复核。
修改规范或正文后需重新检查，不能利用“之前验证过”绕开当前锁定项。事实与正文在同一修订事务中保存。
既有正式稿的历史规范不随作者后来的设定修改重写；如新锁定值与已接受事实冲突，后续装配会暂停并要求复核。

证据包含只证明来源存在，不能证明语义抽取正确。P1 仍需要模型语义检查与作者定稿；复杂倒叙、跨时间有效区间、
谎言/误信和知情推演归 G0017，本阶段不能用简单先后章序替代这些推理。

## 装配顺序与预算

必带项先装：任务边界、本书创意、当前章规划、世界设定、长期规范原文、适用硬规则、锁定实体状态、全部有效前文事实及来源修订。
任一必带项超过预算就停止，不静默截断或丢弃。
随后完整选择建议规则、文风、方法、实体登记、最近三章摘要和匹配历史正文；装不下则记录到省略清单。

预算单位为 UTF-8 字节，包含实际渲染的标题与分隔符；默认 100000，允许 100–500000。它不是 token 计数或服务商上下文上限。
真正发送仍经过 G0008 输入、输出和用量预算门禁；不能绕过请求服务。
省略清单只用于本地解释，不额外拼入发送文本占用未计量预算。

上下文指纹涵盖作品、当前章、规范、发布后的实体目录、适用规则、前文指针和运行；表单草案不当成已发布设定。
结构化规范指纹不含编辑正文，但含章纲、设定及运行；正文另以验证哈希绑定，方便生成后在同一提交用例中替换正文。
锁定字段排序后参与哈希，保证持久化重开稳定。

## 容量和编辑

实体最多 1000 个，别名每实体最多 30，名称/别名最长 100 字符；名称和别名书内唯一。
设定最长 10000 字符，锁定字段最多 50 项，字段最长 100、值最长 2000。
实体编辑草案独立保存；未提交改名不会修改发布目录。改名保留旧名，清空当前锁定字段和值仅取消所编辑项。
实体删除和多项锁定的完整可视编辑暂未开放，避免孤立既有事实引用。
