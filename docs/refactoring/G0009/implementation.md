# G0009 实施方案

基线 `9539b54`；关联 [计划](plan.md)、[记忆上下文契约](memory-and-context-contract.md)、[中文检索夹具](retrieval-fixtures.md)。

## 实际结构与设计理由

`StoryCatalog` 保存作者登记的实体、别名、锁定字段及尚未提交的表单草案；`StoryMemory` 是无 I/O 的领域计算，
从当前修订指针投影前文和验证事实候选。`StoryContextBuilder` 只负责装配有来源与预算的清单，
MainDocument 的新 partial 只处理原生表单和命令。没有新增独立可变事实数据库或向量服务，避免正文和记忆出现双写不一致。

实体 ID 在书内稳定；改名自动保留旧名。关系/归属用关联实体 ID，不能把姓名当主键。
事实实际提交后通过所属 ChapterRevision 获得章节、修订、运行与工作/正式归属；未接受候选不会进入索引。

## 存储与兼容

作品及恢复副本升为 schema 6；读取 1–5 版先验证、做 SQLite 一致性备份，再事务升级。
旧事实键保留为旧格式已接受事实，不捏造实体或证据。新类型化事实必须含实体、类别、字段、证据、正文哈希、运行与规范指纹。
历史正文仍追加不可变，事实与正文同事务提交。旧正式稿不会因之后调整规范而被直接删除，新的冲突在上下文装配时要求复核。

复制作品重分配书/卷/章/修订/运行身份，实体 ID 作为书内 ID 保留；已验证且仍有效的事实规范指纹随新身份重建，
已过期工作稿不能因为复制恢复而重新变成有效。跨书候选仍由 BookId 与上下文指纹拒绝。

## 原生交互

左侧“故事实体与上下文”支持新实体、名称/别名/类型/设定/锁定状态编辑、保存和放弃草案。
草案独立自动保存，切换实体前必须处理草案。当前表单编辑按字段名排序后的首项锁定状态；其他锁定项保持，改名冲突拒绝覆盖。
上下文预览可选择是否包含本轮工作稿、关键词与字节容量，不发起模型请求。
修改正文、前文指针、规范或预览条件后，旧预览明确标记过期。

## 复核补强

GPT-6 复核后，在工作稿提交与定稿入口增加事实规范/正文/运行再校验，避免验证后作者修改设定而旧事实仍被接受。
锁定字段改名不能覆盖其他字段。字典先排序再参与指纹，避免跨进程枚举差异误报过期。
真实原生控件输入、SQLite 重开、复制身份和独立 Debug 暂存 ALC 中的中文姓名/别名检索均建立验证。

本阶段不调用模型生成章节；后续 G0010 复用上下文与 G0008 请求入口完成规划。
