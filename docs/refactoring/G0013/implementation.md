# G0013 实施方案

日期：2026-09-12。基线 `1040bf5`（229 项测试）。

材料领域记录包含用途、来源、全文、分段覆盖、方法卡、文风维度、作者编辑、对比试写、反馈和独立预算 Id。
`MaterialRules` 负责证据和采用门禁；`MaterialCalibrationService` 只进行文件读取、模型文本任务和材料持久化，不持有作品会话。
`MaterialStore` 用版本条件写入独立 SQLite。共享模板工具组合 `MaterialCalibrationPanel`，Document 通过材料服务读取并明确采用，互不操纵窗口。

## 来源与任务

最多接收 20000 字符，单次处理前 1–12000 字符，按 800 字符分段，显示处理与未处理数量。
卡片证据必须逐字出现在已处理段中；推断与直接支持分别标记。方法卡给出条件/步骤/反例/冲突，文风给出规则和自创正反例。
本地证据定位显示实际原文选区。材料中的命令和链接是引用数据，不执行/访问；导入仅接收有界 TXT/Markdown，不加入二进制解析框架。

分析与试写分开预算、各一次请求；源输入和预算先保存。试写提供章纲目标、铺设、阻碍、兑现及 A/B 文本，共用作者给定剧情与逐条事实约束。
每条约束都需要两篇正文中的连续证据。此检查只能确认报告来源，语义和风格仍需作者审阅；允许编辑批注或跳过试写。

## 保存与所有权

草案显式保存，关闭工具自动保存；开始任务前输入必先持久化。任务自有取消源，关闭一本书不取消无关分析，隐藏工具保持对象。
关闭与开始前保存相遇时，取消源提前存在，保存后再次检查取消，不能在关闭等待中启动新付费请求。
保存期间新输入不被当成已保存输入，分析前发现新代数即停止并提示重新发起。

普通保存冲突保留原版本与未保存表单，要求作者明确丢弃/重新读取；不能读到新版本号后套用旧表单覆盖另一方。
模型任务异常只能携带本任务自己已成功保存的检查点，以便保留输入和预算版本。
模型契约同时校验渲染后规范总长度，避免结构合法但超过存储容量。

本书采用追加 MaterialSources 来源快照并更新选定方法/文风；保存为命名模板只创建独立模板 v1。
作品 schema 8，旧库一致性备份后添加空来源集合，副本保留材料来源身份（来源不是作品内实体）。
见 [材料校准契约](material-style-calibration.md)、[结果](result.md)。
