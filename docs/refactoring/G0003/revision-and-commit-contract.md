# G0003 修订与正文/记忆提交契约

## 三种内容状态

| 状态 | 所有者与含义 | 保存行为 |
| --- | --- | --- |
| 编辑缓冲 | Chapter 的标题、提纲、正文与摘要；允许继续输入 | G0002 队列自动保存；不改变工作/正式指针 |
| 工作稿修订 | 不可变 ChapterRevision，属于唯一活动 RunId | 通过预期版本与正文/上下文校验后提交，正文、摘要与事实增量一同写入 |
| 正式稿修订 | ChapterHead.FormalId 指向作者已确认的历史修订 | 从第一章连续定稿；未检查保持未检查，失败修订不能定稿 |

ChapterRevision 保存书内章节身份、父修订、运行/操作身份、标题、正文、正文 SHA-256、摘要、事实增量、
检查状态、前文上下文指纹与创建时间。历史内容只追加；存储 Save 在事务内比较历史前缀，不能从其他入口删改既有修订。

## 提交与幂等

DraftSubmission 显式携带作品 ID、章节 ID、预期工作/正式指针、正文摘要、前文指纹、运行及操作身份。
作品或章节不符、正文已编辑、前文已改变、运行串用、事实旧值不符均拒绝；同操作同内容可重复返回，不能重复追加修订。
复用操作身份提交另一份文本/摘要/事实会报错。

提交先构造并验证新账本，成功写入 SQLite 后才更新会话中的账本。写入失败时编辑缓冲和旧账本不变。
提交期间继续输入的正文等普通编辑会被保留，新账本只合入修订字段；卷章删除/重排/转卷在提交期间拒绝，
避免合并出指向不存在章节的修订。合并结果仍执行完整验证。

## 故事记忆

FactDelta 表示键、预期旧值和新值；null 新值表示删除。事实来源为包含它的章节修订。
读取第 N 章之前的记忆，只遍历前面的有效指针，正式查询只用正式稿，工作查询可使用本轮工作稿。
投影核对事实旧值，不把候选或未来章节加入正式状态。前文指纹包含作品身份及前序章节/修订身份，不能跨书复用。

定稿必须按顺序，并且编辑正文仍与待定稿工作稿一致。正式章节的顺序与来源指纹也在聚合验证时核对，不能通过普通
Update 重排正式章节来静默改变故事记忆。前文工作稿后面已有工作稿时，重写前文需要先放弃本轮工作稿。

## 放弃、回退和复制

放弃清除本轮工作指针与活动运行身份，保留正式指针、编辑缓冲和全部历史。回退清除所选章及后续正式指针，
同时撤销本轮工作稿；记忆随有效来源重算，不能只回退正文而遗留后续事实。

恢复为独立作品会重分配书、卷、章、修订、运行及操作身份，保留历史正文与状态，重建当前有效上下文指纹。
源项目与原恢复文件继续保留。仍使用纯文本事实键，后续实体结构化与更复杂时间查询按 G0009/G0017 扩展。

文学质量、事实自动提取和模型检查不属于本阶段完成度。人工工作稿可以是未检查状态，UI 始终保留这一事实。
