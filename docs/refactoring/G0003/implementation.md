# G0003 实施方案

[计划](plan.md) · [修订契约](revision-and-commit-contract.md) · [迁移契约](schema-migration.md) · [结果](result.md)

## 设计思路

采用不可变修订及工作/正式指针；复用现有作品聚合事务，不另建一份可以与正文失配的可变记忆库。
领域层负责状态合法性、版本比较和事实投影，应用层负责单写入及并发合并，基础设施负责事务与已知格式迁移。
使用现有窄存储端口，没有增加通用事件框架、通用仓储或独立服务进程。

| 修改位置 | 实际职责 |
| --- | --- |
| `Domain/Revisions.cs` | 修订、指针、事实增量、提交、人工定稿、放弃、回退、上下文指纹及身份复制 |
| `Domain/BookProject.cs` | 关联修订账本、保存摘要编辑缓冲、聚合合法性；独立复制保留并重映射修订历史 |
| `ProjectSession.CommitRevisionChangeAsync` | 同一写入门内提交正文与记忆；失败不改变当前账本；并发正文编辑保留 |
| `ProjectStore` | schema 2、一致性备份迁移、事务内格式和历史前缀校验 |
| `MainDocument` / `MainView` | 本章摘要、工作稿/正式稿状态和人工命令；普通保存不触发定稿 |
| `RevisionTests`、`DocumentEditingTests` | 领域转换、实际事务故障、迁移、并发和真实应用入口回归 |

## 界面行为

“本章提纲与修订”内可填写摘要、提交工作稿、人工定稿、放弃本轮工作稿、回退本章及后续定稿。
摘要编辑也自动保存。历史正文不随编辑框修改；工作稿与当前编辑不同会显示“有未提交修改”，禁止误定稿旧正文。
人工提交状态为“未检查”，人工确认只推进正式指针，不能将该状态篡改为 AI 检查通过。

编辑区支持滚动，展开修订操作后不会迫使整个窗口和固定状态栏被裁切。完整版本差异、逐项记忆审阅及批量操作
仍归 G0014/G0015；本阶段的事实测试夹具不表示已实现 AI 提取。

## 审查后修正

GPT-6 基于指定的四个源码文件完成只读审查，提出三项问题：提交期间结构删除会破坏合并；正式章节重排可改变
事实投影；格式校验与写事务有竞争窗口。分别通过结构冻结与合并验证、正式上下文与事实旧值检查、事务内格式复核解决。
另补充提交携带作品身份，阻止相同章节身份的跨书候选被误用。所有修改通过阶段回归。
