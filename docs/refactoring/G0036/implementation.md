# G0036 审计和评阅方案

开发工具 `AnalysisProbe audit` 直接使用生产 `NovelAnalysisReportService`。重复三次打开同一已完成报告，核查完整状态和哈希；枚举报告中所有被引事实及其去重证据，逐一调用实际定位服务，比较选区文本与保存引文是否逐字符一致，同时测量定位耗时。此模式不构造模型连接，也不读取标准输入密钥。

机器审计输出 `audit.json`，包括来源、报告版本、各阶段节点数、结论/事实/引用数量、已知/未知用量及性能。它只证明结构和机械引用，不证明结论受原文语义支持。

人工包 `human-review.md` 提供 60 个按来源位置等距选取的原文片段、独立标注空栏、76 条实际核心结论和五项文风/综合评阅表。所有答案与指标保持“待填”。这些片段是辅助材料，不能冒充预先完成的人工标准答案；本次在模型运行前没有取得人工标注，不能事后宣称已完成盲评。严格长篇评测应先固定独立标注，再运行并评分。

```powershell
dotnet run --project tools/AnalysisProbe/AnalysisProbe.csproj --no-restore -- audit - '<已有运行目录>'
```

每次创建新评阅子目录，并更新 `audit-path.txt` 指向最新目录，不覆盖过去的人工作业。真实小说文本、引用、原始模型输出和数据库保留在忽略目录；Git 仅保存工具、脱敏摘要、验收矩阵和限制。
