# TXT 来源、编码与全文覆盖契约

日期：2026-09-12。

## 预览与保存

`PreviewAsync` 读取明确的 TXT 并返回解码编码、警告、原文快照、章节和单元。`ImportAsync` 保存原预览；不再次访问同一路径。显示预览时如需改变编码或切分参数，重新建立预览，旧预览不混用新参数。

支持 UTF-8、UTF-16 LE/BE、UTF-32 LE/BE 和 GB18030。BOM 是明确编码标志；没有 BOM 时自动编码只是推断，界面必须显示实际编码与核对提示。超过 20 MiB 字节或 200 万 UTF-16 字符明确拒绝；空文本、解码损坏和不符编码的 NUL 也拒绝。

## 分章与范围

识别到的标题与之前的卷首文字均入库，目录或重复标题不自动删除。分章预览提供原文位置，阶段 G0035 再接入用户范围操作。未识别标题时使用“片段 N（未识别章标题）”，不能声称准确识别章节。

初始单元目标 6,000 字符、前后上下文各 300 字符，属于可调整的本地切分设置；它们不是模型上下文保证。每个 Body 连续覆盖所属章节，Context 包含 Body 并可重叠；全部 Body 拼接必须等于所选正文。标题超长只缩短显示字段，原文仍保留。

来源存储可保存超过 1,000 个单元，但现有模型预算最多 1,000 次请求。后续运行预检必须考虑整合、汇总、重试请求；不能把来源导入通过描述为所有规模均能直接在单个预算中分析完毕。

## 离线验证入口

从项目根目录执行：

```powershell
dotnet run --project tools/AnalysisProbe -- import <本机TXT路径> <新的输出目录>
dotnet run --project tools/AnalysisProbe -- benchmark - <新的输出目录>
```

import 按文件实际内容统计，不推断原小说导出范围之外的章节。benchmark 生成 200 万字符合成文本并测三次导入/重开，只用于工程容量与性能，不能用于证明文学分析质量。

测量结果包含字符、字节、来源哈希、章节/单元、覆盖、导入/重开/列表耗时和每 10ms 采样的托管内存增量；内存采样可能漏掉极短分配峰值，不能声称系统级精确峰值。
