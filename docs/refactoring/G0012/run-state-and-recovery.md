# 连续运行状态与恢复契约

## 作者流程

设置单章字数/修正次数，再设置 3–5 章范围、总请求与 token 上限，选择是否自动补齐章纲，开始连续创作。
通过必要审校后自动保存工作稿并续写下一章，无需逐章接受；最终定稿仍由作者执行。
“完成本章后暂停”保留整个已接受章节；“立即取消”停止在途请求，已有工作稿与候选保留。
读取记录后可调整预算并明确继续。失败/截断/未知用量会阻止新增请求，需先复核候选，再明确接受可能计费的风险。
结束旧运行保留所有稿件，允许新建运行；已完成运行不能继续。

## 状态

Queued 排队、Running 规划/生成/审校、Committing 本地事务、Paused 检查点暂停、NeedsAttention 阻塞问题、
Completed 全部工作稿完成、Cancelled 作者取消、Interrupted 发现失去执行所有者的旧检查点。Failed 为记录模型预留状态；当前可处理异常统一进入 NeedsAttention。
进行中的单章细节和部分正文可从单章候选入口读取。重开不会自动发送付费请求。

## 中断矩阵

| 中断位置 | 恢复处理 |
| --- | --- |
| 规划生成尚未返回 | 请求账本保留可用结果；明确继续才可能新增规划请求 |
| 待写规划已记录、作品未写 | 写入同一个完整快照，保留固定身份 |
| 规划作品已写、运行未推进 | 对照待写快照并推进，不再请求规划 |
| 正文/审校/修正中断 | 部分候选与请求记录保留；用量风险未明确处理则拒绝新增请求 |
| 候选 Ready、事务未开始 | 使用保存的候选提交，不重复生成 |
| 作品事务已提交、运行未推进 | 对照预期单条提交，确认后前移一次 |
| 检查点之外存在作者修改 | 停止并保留现有内容，重新核对/结束旧运行，不能自动覆盖 |
| 检查点写入瞬时失败 | 不消耗序号，尝试保存待处理状态；持续存储故障会明确报错 |

每个操作使用明确 Id；本地去重不意味着远端恰好一次，也不承诺重试生成相同文本。
运行库 `continuous-runs.db`、候选库和请求库是本机数据；作品 `.noveldb` 只保证已保存规划、编辑和修订可移植。
运行检查点目前保留完整作品快照，长篇体积/归档优化归 G0019。恢复阶段保守要求快照一致，规范或正文变更后需要作者处理旧运行。
