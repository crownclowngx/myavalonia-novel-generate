# 预算与并发契约

同一运行的规划、生成、审校和局部修正共用预算 Id。实际请求次数取决于规划是否就绪、问题与修正轮次，不按每章固定三次计费。
默认三章、20 条请求、1000000 token 上限；每章字数与最多修正次数沿用单章区域。上限设置不代表立即花费。

请求发出前事务预留输入 UTF-8 字节估值、Schema、输出上限和 CLI 余量；这不是精确 tokenizer，也不是远端账单硬封顶。
已知用量按实际值计，未知用量保持预留；实际用量超过预留时记录实际并阻止超预算的后续请求。
结束旧运行不会清除账本。继续只能保持或提高已建预算，不能在单次请求内偷偷改上限。

失败、截断、未确认结束及完整响应但用量未知都默认阻止新增请求。作者明确接受风险后，账本只增加 RetryAcknowledged，
原状态、正文、失败代码和计费值保持。此授权只针对当时已有记录，后续新增不确定请求仍需要再次复核。

当前进程同一连接一个在途请求；排队不预留，排队取消不计发送。不同连接可并发，但同一本书的连续运行受文件执行锁和数据库唯一活动约束保护。
连接并发限制按本机连接 Id，未宣称跨多个独立 Host 进程或不同连接记录共享同一远端账户的全局限流。
作品会话仍控制 `.noveldb` 写租约。连接修改/移除密钥会在下一条实际请求前被连接服务阻止。

分析/试写继续使用独立预算 Id，不混入正文运行；具体任务由 G0013 接入。没有自动网络重试或无限循环。
