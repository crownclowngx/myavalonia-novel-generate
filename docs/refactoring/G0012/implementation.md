# G0012 实施方案

日期：2026-09-12。基线 `b1c1019`（211 项测试）。

`ContinuousRunService` 复用规划和单章服务，按章串行编排；`ContinuousRun` 保存策略与检查点，`ContinuousRunStore` 提供独占运行锁和 SQLite 版本更新。
界面只发起开始/暂停/取消/读取/继续/结束动作，按钮与单章流程复用作品会话；不新增通用工作流框架。

## 顺序与一致性

开始要求原作品保存成功，冻结当时作品快照、连接绑定、范围、字数、修正次数和总预算。需要补齐规划时消耗同一预算。
规划先把完整待写快照存入运行记录，再写作品，随机卷章与实体身份不在恢复时重新生成。
每章生成审校 → 持久化候选 Id 和提交检查点 → 原子提交工作稿 → 核对只有预期提交变化 → 推进运行。
若作品已提交而日志未推进，恢复用提交前快照重演领域变换，再对照实际随机修订 Id/时间；其余字段必须完全相同。
任何作者修改均不能借“恢复成功”被吞掉，模型和正式稿不自动重写。

检查点序号仅在存储成功后更新内存，瞬时失败可保存停止原因；SQL 拒绝旧序列覆盖。
同书运行用独占文件句柄保护执行，SQLite 部分唯一索引保护未结束任务；读取优先返回仍活动的运行。
恢复历史运行前再次检查是否已有另一活动任务，避免旧运行写入规划后才发现冲突。

## 预算与停止

同连接在当前进程内最多一个在途请求，排队取消不产生预算预留；不同连接可独立工作。请求预算继续由 SQLite 事务检查。
明确继续可提高预算；未知用量仍扣保守预留。勾选已复核风险只允许新增请求，不把旧请求标为成功，也不清除用量。
暂停在完整章节提交后停止；立即取消传给模型，已进入的本地事务完整结束并记录。读取中断记录只核对运行锁并标记 Interrupted，不调用模型。

见 [运行恢复契约](run-state-and-recovery.md)、[预算与并发](budget-and-concurrency.md)、[阶段结果](result.md)。
