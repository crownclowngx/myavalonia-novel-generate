# G0031 实施方案

日期：2026-09-13。状态：阶段已验收，见[结果](result.md)。

## 提取职责

`NovelChunkAnalysisService` 只执行一次有界提取，操作 ID 和共享预算由调用方提供。它验证来源、冻结连接、生成带版本的输入指纹，并复用 `ModelRequestService`；没有内部重试器。

`ChunkAnalysisContract` 使用严格 JSON 构造参数与枚举规则。Summary、Entities、Findings、Gaps 均必需；六维必须存在 Findings 或显式列入 Gaps，不能漏维度；局部观察与仍存在的未知项可以并存。实体提及与分析观察分离，保留角色说法、梦境、回忆、计划及时间线索。

## 证据与恢复

原文按行/段落组织，单段最多 600 字符，不切断 Unicode 代理对。v2 模型只给段号，本地从该段取回精确文本和来源区间，错误段号直接拒绝。相同文本出现在不同段落时也有不同段号；不接受模型自己改写的 Quote 字段。证据命中只证明引用存在，语义是否支持结论仍按质量口径评阅。

实体提及和结论 ID 从操作 ID、类别及数组位置确定生成，同一原始响应在重启后解析不会生成不同身份。这为 G0032 的账本恢复提供稳定输入。

## 实测发现与协议修复

本次账户 `/models` 实际返回 `deepseek-flash` 与 `deepseek-v4-pro`。真实验证使用前者；公开资料中的 `deepseek-v4-flash` 不作为当前账户模型可用性的依据，现有用户默认配置不因此修改。

实际章节请求曾在思考额度耗尽后返回 `finish_reason=length`、无可见正文。原适配器把这种情况作为 Protocol 抛出，导致已返回的用量没有进入账本。现在合法空截断返回 Truncated，统一请求服务先保留有效用量，再判断正文是否合法；完整但空的正文仍拒绝。新增两个协议回归测试覆盖两种情况。

提取小样改用 `deepseek-flash`、关闭思考、16384 输出上限。v1 得到的结构化结果中存在“簿”被改为“谱”等原文抄写错误；v2 改为段号引用，并保留可直接阅读的中文 JSON 输入，减少 Unicode 转义导致的额外 token。此前失败候选和未知用量保留，不回填猜测的 token。额外协议探针仅显示字段形状，不保存推理或请求头；后续代码阶段按本次累计请求与用量记录全部测试成本。
