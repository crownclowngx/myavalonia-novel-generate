# G0033 实施方案

日期：2026-09-13。

`NovelAnalysisIndex` 按正文顺序建立完整提及/事实索引，每项保留原始证据和所在单元。后续模型引用短整数编号，本地沿索引回到来源快照，避免模型重抄原文或生成坐标。

`NovelIntegrationPlanner` 先以同类别的姓名/别名形成身份候选，随后按最多 60 项、材料 JSON 最多 60000 字符分批。词面匹配不执行身份合并。事实按维度有界分批；每个节点记录 Selection 与相关提取节点依赖。规划只在完整阶段边界追加，追加与检查点在同一事务内保存，不能在提取尚未完成时提前建立伪完整整合。

`IdentityAnalysisContract` 检查引用归属、重复分组、类别与不确定性。遗漏提及明确保留为未知单例。`NovelIntegrationSnapshot` 对 Uncertain 的多提及组保留独立身份及可能同一人的连接，避免将歧义直接采纳。身份 ID 在当前运行内由操作与成员确定，重复恢复稳定；新版映射保留旧运行与依赖记录。

`ContinuityAnalysisContract` 保存条件、例外、故事时间和叙述来源，Role 区分规则、冲突、事件、关系、目标、阻碍、行动、结果、主支线、伏笔等。未消解的事实矛盾（Contradiction）必须标为 Uncertain；传闻、角色说法、梦境、计划及未确定输入不能无条件升级为确定客观事实。此检查只守住可识别的类别边界，不宣称自动证明语义正确。

`NovelAnalysisRunService` 仍负责所有请求与结果提交，完成态新增“整合完成”，没有专题与综合报告时不标为最终完成。预算 ID 在提取到整合的修订中保持不变；整合期间继续保留最多 7 次/400000 token 的后续报告额度。实际整合计划超过剩余请求额度时暂停，不新建预算绕过限制。

详见[身份与连续性契约](identity-continuity-contract.md)。
