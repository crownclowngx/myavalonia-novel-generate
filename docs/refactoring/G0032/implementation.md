# G0032 实施方案

日期：2026-09-13。

`NovelAnalysisRunService` 持有运行状态、顺序依赖、暂停/恢复与总预算。`IAnalysisNodePreparer` 返回带业务契约的有界请求，当前生产实现委托既有单元提取构造器；后续整合/专题可扩展此任务边界，不能自行发送付费请求。`ModelRequestService` 仍是唯一请求入口，公开相同的保守预留公式供阶段预算检查使用。

`AnalysisRunStore` 使用独立 `reference-runs.db`，不改写不可变原文库。每次只保存轻量运行与一个结果，结果含内容哈希；状态和结果使用同一 SQLite 事务。来源、冻结连接、切分计划、已完成节点不能原地覆盖，预算只能增加，版本必须递增。外来/未来数据库在写入前拒绝。操作系统文件锁按预算身份持有，因此同一实验的多个修订也不能并发发送。

发送前先将节点标为 Running 并存入操作 ID。重开时用该 ID 查总账本：没有预留记录表示尚未越过发送边界；完整响应重新经过当前契约验证后本地提交；截断、失败或在途请求停在 NeedsAttention。请求库与运行库之间不使用分布式事务，以账本重放补偿提交窗口。显示回调失败不会回滚成功结果。

暂停在完整节点提交后的边界生效；取消传递给活动请求，若响应已经完整返回则先保存结果。明确恢复可能新增操作 ID，但旧状态、片段和已知/未知费用全部保留。预算 ID 不随修订变化，阶段预留在每次请求前重新核对；总账本事务再次检查最终上限。

每个运行保存自己的切分。`NovelTextPartitioner.Rechunk` 在同一原文、同一章节身份上生成新的单元范围，旧运行仍可读取。缓存指纹包含来源身份/哈希、正文与上下文范围、冻结模型、契约版本和完整提示；修改只使相关节点及其下游无法复用。新的独立实验需由调用方明确建立；修订实验使用 `previousRunId` 继承累计费用。

详见[恢复与预算契约](run-recovery-contract.md)。

真实运行暴露出确定性 Kind 与叙述来源 Narration 混用。提示 v3 加强允许值说明，契约仍为 v2，禁止猜测修复无效枚举。每个提取节点冻结提示版本；修订默认对未完成节点使用新版本，已完成节点保留原版本以复用有效缓存。离线阅读验证保存时指纹和原文，不用新版提示使旧结果失去阅读能力。

Gaps 的兼容校验修正允许同维度多个独立未知项，总量最多 24 条；结构及枚举不变，保留 v2 输入身份。来源证据、六维覆盖、缺口文本边界继续校验。此前失败结果与费用保留，不把旧账本静默改成成功。
