# G0029 实施方案

日期：2026-09-12。对应 G0029-01–05。

## 实际职责

- `Domain/Analysis/ReferenceSource.cs` 固定全文容量、书目、不可变来源、章节与分析单元；导入清单验证所有区间连续且身份一致。
- `Domain/Analysis/AnalysisEvidence.cs` 固定六维提取结果与精确证据；证据校验不代替语义质量判断。
- `Application/Analysis/IReferenceSourceStore.cs` 是唯一新增的外部存储端口，提供原子导入、读取、分页和乐观改名。
- `Infrastructure/Persistence/ReferenceSourceStore.cs` 使用现有 SQLite 连接基础，新增独立库及 application_id；导入四类记录在同一事务中保存。
- `Plugin/NovelGeneratePluginServices.cs` 注册来源存储。注册/构造不访问用户数据库，首次用例才打开库。

详细规则见[数据契约](analysis-data-contract.md)；原创夹具、用户样本元数据与固定性能口径见[评测基线](evaluation-fixtures.md)。所有新增关键类型使用中文注释解释职责、坐标、事务及质量边界。

## 为什么这样设计

来源与创作项目分开，避免参考书历史污染工作稿/正式稿。列表和改名只处理小书目，原文保存独立 TEXT/BLOB。领域不做 SQL 或编码探测，存储端口不暴露连接，保持 SRP 与依赖反转；现有模型与任务能力后续按原边界复用。

未引入通用数据仓库、统一任务框架、第三方服务或新依赖。G0029 固定运行/报告契约和最小分析字段；实际运行类型在 G0032 随调用方建立，避免预先创建无行为的状态机。

## 本地验证设计

新增真实 SQLite 测试覆盖重开、原字节/CRLF、乐观并发、重复导入、分页和双书；使用 SQLite trigger 在章节插入时主动中断，验证已经插入的书目和正文一起回滚。未来 schema 与外来库检查同时比较前后数据库字节，证明拒绝后未写业务内容。

领域测试覆盖漏段、重叠、代理对、超大偏移、显式排除、重叠上下文、重复引文精确定位、伪造/过期证据与容量边界。磁盘正文篡改和单元删除必须被读取验证拒绝。DI 测试检查真实生产注册且不读取作者文件。

首次测试发现 xUnit 对 `ImmutableArray` 的断言选择了不合适的相等比较；改为逐元素数组比较后通过。来源记录内容没有为绕过断言而改写。

## 本轮用户补充

真实模型指定 DeepSeek Flash，密钥只使用会话内存；测试输入为用户提供的部分章节导出文件。G0029 仅完成本机元数据检查与后续预算设计，未发送原文或执行付费分析。此样本的完整分析不等于原小说全文，百万字符验收仍需独立证据。
