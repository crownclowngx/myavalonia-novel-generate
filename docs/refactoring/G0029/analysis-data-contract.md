# 参考小说来源与分析数据契约

日期：2026-09-12。适用阶段：G0029 起。

## 设计思路与 SOLID

来源领域只验证身份、区间、证据及容量；导入服务负责文件和编码；存储适配器负责 SQL 与事务；运行服务负责付费调度；视图负责展示和用户意图。一个真实存储边界使用一个窄端口 `IReferenceSourceStore`，不引入通用 Repository、事件总线或代理框架。

`ReferenceBook` 是轻量书目；`SourceSnapshot` 是不可变来源；`ReferenceSection` 是覆盖全文件的章节区间；`AnalysisChunk` 将所选正文切成连续、不重叠的处理区间，另带可重叠 Context。`AnalysisEvidence` 固定来源 ID、正文哈希、精确 UTF-16 区间和引用。`AnalysisFinding` 固定六维与明确/推断/不确定状态。

领域只使用 BCL，不依赖 Avalonia、Host SDK、HTTP 或 SQLite。应用依赖存储端口，插件组合根选择 SQLite 实现；测试可替换外部模型，存储测试仍用真实 SQLite。

## 输入与容量

固定单书上限为 2,000,000 个 UTF-16 字符、20 MiB 原始字节，最多 10,000 个章节/片段与 10,000 个单元。来源库可以保存大量单元，但当前统一请求账本每预算最多 1,000 次请求；调度阶段必须在发起前确保全任务请求规划与重试预留不超限。

正文保持解码后的原始 CRLF/LF、标点和 Unicode，不作内容规范化。这样所有坐标直接用于原文选择；UTF-8 哈希只标识解码文本，原始字节哈希另存。原字节与实际编码的一致性由 G0030 导入边界负责，领域不做编码猜测。

区间使用 `[Start, Start + Length)`，必须非空、在正文内且不拆分代理对。书目字符数等于来源正文长度。章节连续覆盖所有原文；Included=false 的章节显式排除；单元 Body 连续覆盖所有 Included 章节，Context 包含 Body。覆盖分母是所选 Body 区间并集，不计算重复上下文。

## 存储与并发

独立文件为用户数据目录中的 `reference-analysis.db`，application_id 为 `0x4E524546`，初始 schema 为 1。四张表为书目、来源、章节和单元。来源文本和原始 BLOB 不在书目 JSON 内，改名和分页列表不重写正文。

导入前验证完整清单，再用同一事务插入全部记录。任一 SQL 失败时整体回滚；重复 ID 拒绝覆盖。书目从 Version=0 导入到 1，改名比较旧版本并递增。读取完整来源后再次校验哈希、书目身份、区间和覆盖，损坏内容不能成为待分析输入。

初始化在事务内核对 application_id、user_version 和现有表。只有空库允许初始化；外来库或未知版本拒绝。初版没有旧分析库迁移；未来新增运行表时必须设计已知版本迁移与一致性备份，不盲目接受未来 schema。

## 后续运行和报告契约

G0032 才实现运行节点和事务类型，G0029 不预建无调用方的状态机。其必须遵守：一个运行绑定参考书来源、模型配置与总预算；节点保存操作 ID、输入依赖指纹、状态和结果；节点结果与完成状态同一本地事务提交。既有请求账本为单独数据库，使用操作 ID 恢复核对，不虚构跨库原子事务。

G0034 报告保存六个 `AnalysisSection` 与综合结论、来源版本、处理覆盖和不确定项。完整标志由应用计算，模型不能自行声明全文完成。引用精确存在只证明机械定位，语义准确性按人工评测另验。

用户指定本次实测使用 DeepSeek Flash；按[官方 Chat Completions 文档](https://api-docs.deepseek.com/api/create-chat-completion/)核对，本专项实测选择 `deepseek-v4-flash`、`https://api.deepseek.com`。保留已有用户连接配置，不因本专项试验重写全局默认值。一次性密钥仅进入会话凭据或实测进程内存，不进入源码、文档、测试夹具或报告。

首个短片段验证最多 2 次请求、150,000 保守预留 token；用户所给约 5 万字符文件的完整实测初始总预算最多 80 次请求、3,000,000 保守预留 token，包含补查和重试。仅在对应分析功能实现后运行；预算是上限，不是必须消耗的额度，未知/失败按现有账本暂停。后续百万字符实测需另有实际文件与预算范围。
