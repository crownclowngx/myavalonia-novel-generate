# 小说创作工作台质量基线与验证要求

日期：2026-09-12。状态：持续适用的验证要求；各阶段实际结果单独归档。

适用于[实施总计划](../implementation-plan.md)各 G 阶段。以本项目现有约束为基础，采用清晰分责、朴素模式、必要的中文契约注释及随实现同步的测试和文档；不复制其他插件历史任务对 CI、发布或工具使用的专属限制。

## 1. 工程约束

1. 唯一生产程序集为 Plugin；Standalone、测试、Fake 和开发 Stub 不随正式包交付。
2. Domain 不依赖 UI/SDK/HTTP/SQLite；UI 通过应用用例操作内容，不直接执行 SQL、拼提示词或管理长期密钥。
3. 使用窄端口隔离实际外部依赖，不为每个实体建立接口，不引入通用代理框架、事件总线或额外容器。
4. 保持已有 PluginId 和主 DocumentTypeId；两个 Tool 使用稳定身份，每个只注册一次，贡献根不在私有 DI 重复登记。
5. 状态由正确所有者管理：Document 展示本书，项目会话管理写入，服务管理跨页任务，Tool 展示共享资产。
6. 每次运行有明确项目、修订、规范、连接配置和预算；不依赖全局当前对象，也不把 View 保存在长期任务中。
7. 原生 Avalonia 界面依据产品示意实现，复用 Host 资源与公开端口，不引用 Host 私有 Dock、容器或反射入口。
8. 关键注释解释版本检查、取消与落盘、规则作用域、状态隔离、费用不确定性和失败恢复的理由。

## 2. 数据、模型与秘密

| 维度 | 必须成立的约束 |
| --- | --- |
| 内容归属 | 每本书有独立配置快照、实体、正文、历史和记忆；模板升级不自动覆盖作品 |
| 保存 | 编辑保存、工作稿提交、人工定稿分别表达；内容与对应事实/摘要同事务 |
| 版本 | 提交核对预期修订、正文与规范；旧结果保留为候选，不能直接续写 |
| 关闭 | 取消网络与必要本地排空分开；失败缓冲不随 View 销毁；有界退出不等待整章完成 |
| 记忆 | 按作品、状态、来源版本与时间过滤；候选和未来规划不当既成事实 |
| 规则 | 硬规则确定装配，不参与相似度淘汰；未完成检查不通过，修复后重新检查 |
| 预算 | 请求、在途预留、重试、返工与分析均受控制；未知用量不记零，无无限循环 |
| 凭据 | Key 独立保存，按授权连接使用；不进入项目、模板、导出、备份、日志或 Workflow JSON |
| 模型输入 | 只发送明确选定的资料；材料或模型响应中的命令不取得执行权 |
| 恢复 | 本地操作不重复采纳；不承诺远端恰好一次、相同续接文本或未保存按键零丢失 |
| 备份 | 活跃 SQLite 使用一致性备份；schema 迁移前备份，未知新版本拒绝盲写 |

## 4. 本地验证命令模板

在项目根目录执行以下适用命令。可使用 `./tools/verify-local.ps1` 执行本地检查；实际执行结果见阶段档案。

```powershell
dotnet restore NovelGeneratePlugin.slnx --locked-mode
dotnet build NovelGeneratePlugin.slnx -c Debug --no-restore -warnaserror
dotnet test NovelGeneratePlugin.slnx -c Debug --no-build
dotnet format NovelGeneratePlugin.slnx --verify-no-changes --no-restore
```

新增依赖时先正常 restore 更新并核对锁文件，再进行 locked restore；不要降低哈希校验来规避包来源问题。新依赖同时核对统一版本、项目引用、私有资产及其传递依赖。SDK/Avalonia 等共享资产不作为私有包带入交付物。

G0001 已建立 `tools/verify-local.ps1` 和 `tools/check-docs.ps1`。脚本应检查命令退出码并保留摘要；测试数量、跳过项和原因据实记录，必要测试不能被跳过后仍记为通过。

已有不相关格式差异先记基线，再验证本阶段修改范围；不为通过格式工具而批量改写无关文件。实现/依赖变化执行适用检查；纯文档阶段仅核对链接、锚点、编号、状态和需求映射。HTML 更新使用现有生成脚本并核对正文及图文状态一致。

## 5. 真实 Host 与真实模型

真实 Host 检查使用明确的测试目录和作品副本，记录实际 Host/插件版本、依赖与操作。临时联调按[部署协议](../deployment-and-release.md)生成干净插件目录，不复制普通 bin，不清理 Controls 根目录或其他插件，不热替换运行中的插件。

P0/P1 需要真实 Host 行为证据；缺少环境时可以完成独立本地工作，但相应验收保持未完成。正式 Release、ZIP 和发行验证在选定版本的 G0028 执行，不混入每个小阶段，也不永久删除交付要求。

真实模型评测仅在模型连接、输入范围和预算明确时执行。常规测试不得依赖个人 Key 或默默产生费用。若任务范围已明确包含相应受预算评测，按既有范围执行；缺少必要配置则记录具体缺项，不伪造结果。

样稿评测记录输入条件、版本、实际调用、已知/未知用量、作者评价、接受比例和修改时间。模型自评分仅为辅助信息；同一套样稿和规则用于版本对照。个人原文和 Key 不进入公共结果摘要。

## 6. 完成状态与证据

每阶段完成检查：范围中的工作项已实现；相关自动化通过；声明必须的真实环境/人工验收有证据；源码和计划对应；方案、结果、索引已同步；偏差和剩余工作明确。

“计划已完成”“工程候选已验证”“阶段已验收”“交付包已验证”“已发布”分别记录。任何一项缺失，都不得用另一层的证据代替。必要检查通过后不为增加测试数量重复运行无关检查。
