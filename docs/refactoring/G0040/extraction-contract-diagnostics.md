# 提取契约诊断协议

## 真实问题与解释

本次失败响应为完整 JSON，已知输入 5546、输出 21871，累计本次用量为 27417 token。它不是总预算耗尽、单次输出截断或提示装不下。

原始候选包含 19 个实体、36 条结论、5 条缺口；其中四个实体的 Evidence 分别有 11、11、10、9 条，超过本地每项 8 条的上限。首个错误：

```text
结构校验失败，位置：$.Entities[1].Evidence：条目数量须为 1–8，实际 11。
```

数组下标从 0 开始，因此 Entities[1] 是第二个实体。该提示不显示人物名、小说原文、密钥或服务端错误正文。

## 修复边界

| 规则 | 行为 |
| --- | --- |
| Entities / Findings 的 Evidence | 必须 1–8 条，优先选择 1–3 条有力出处 |
| Gaps 的 Evidence | 可以省略；显式提供时同样 1–8 条，空数组被拒绝 |
| 引用段号 | 必须位于本次实际提供的 Passages 中 |
| 其他数组、文本字段 | 新 Schema 声明已有容量，本地仍执行数量、必填和有效值检查 |
| 格式或业务错误 | 完整且用量已知才允许同一节点最多一次纠正；位置和实际数量进入纠正提示 |
| 历史候选 | 不截断、不拼接、不替作者选择证据，不伪造成功或减少已计费用 |

计数只说明违反哪条规则，不证明引用在语义上支持结论。JSON Schema 提示不能保证模型每次都遵守约束，重复失败依然停止。

## 旧运行与使用方式

旧 v2/v3/v4 运行继续沿用原提示。要使用完整 v5 约束，先在现有运行的安全停止点读取进度和复核费用，再按当前范围新建修订；范围不变的成功节点保留旧结果与参数，未完成节点使用 v5。
