# G0004 模板快照、保存与恢复契约

## 三种内容

| 对象 | 保存位置 | 修改语义 |
| --- | --- | --- |
| 模板草案 | 用户目录 `catalog.db` 的 templates 表 | 可编辑，保存不改变旧版 |
| 模板版本 | 同一资产的 Versions 历史 | 只追加；旧前缀不可删除或原地覆盖 |
| 本书规范与来源 | 本书 `.noveldb` | Profile 可独立编辑；AdoptedTemplate 记录最近一次来源版本、选择维度和完整源内容 |

采用动作覆盖所选维度，保留未选维度。它不持续订阅模板库，也不把本书更改写回库。
连续从不同模板采用时保留最终 Profile 和最近一次采用来源；完整多源谱系留给后续组合模板阶段。
归档停止新的采用，已有书可离线读取；源资产被外部移除也不影响已保存的本书快照。

## 并发与失败

模板 ID 永久稳定，数据库 Revision 是并发版本，模板版本 Number 是作者保存的内容版本，两者不能混用。
每次更新在事务内核对目录 schema、数据列与快照身份/版本、旧版本历史前缀，再比较预期 Revision 写入。
另存为已发布模板先构造包含 v1 的资产，再一次插入；失败重试不遗留无版本的半成品。

Tool 保存期间捕获编辑代数，成功只认可该次保存的内容。关闭操作串行等待已有命令并禁用新的命令；
程序侧若在等待期间更新表单，关闭返回失败，不能把更新代数当作已保存。隐藏或重建 View 保留共享模型。
保存失败写 `TemplateRecovery/<唯一标识>.json`，临时文件 Flush 后原子替换；关闭前回读验证当前代数。
库和恢复均失败则保留内存草案、阻止 Standalone 关闭。恢复创建新资产和新版本身份，原模板与恢复文件均保留。
损坏 JSON、缺失 Asset 或文件不可读显示为失败项，不遮住其他恢复项。

## 格式演进

作品 schema 3 增加 Profile 和 AdoptedTemplate，恢复文件新写入格式 3，读取兼容 1/2/3。
作品格式 1/2 先验证，再用 SQLite BackupDatabase 生成 `.before-v3-<唯一标识>.noveldb`；
写事务内复核原格式后补入默认字段、提升作品写版本并更新 user_version=3。未知格式拒绝写入。
旧正文保持编辑稿，不自动变为已检查稿或正式稿。

目录 schema 保持 1，以兼容方式新增独立 templates 表。最近项目更新不触碰模板表。
项目和模板均不包含凭据；本阶段尚未实现模型连接，也不读取 Codex 认证缓存。

## 验证边界

本地原生控件测试确认中文输入、发布、视图重建和快照持久化；组合测试确认 Tool 单例与 Document 隔离。
真实 Host 的隐藏、重新打开、卸载与退出待 G0015 联调；`IClosePreparation` 是插件自己的开发关闭契约，不是 SDK 接口。
