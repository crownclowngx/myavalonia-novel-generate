# 整本小说分析保存与模板自动接通改造执行计划

日期：2026-09-13。改造编号：G0041–G0044。状态：G0041–G0043 本地已验证，G0044 验收推进中。

本文件将“确认并完善分析保存”与“已有报告自动转创作模板”作为一次改造管理，沿用 G 四位编号拆分阶段。计划编制后用户已授权按阶段实施、验证和分步提交；真实模型验收按明确的连接、范围和预算执行，插件发布单独记录。

## 1. 改造目标与完成口径

用户已经完成一本小说分析，希望保留分析成果，并直接将综合结论、世界观、人物体系、故事方法和文风转换为可复用模板。

最终流程：**已保存的整本分析 → 选择报告与模板维度 → AI 提炼创作规范 → 自动保存新模板草案 → 编辑并保存版本 → 在不同新书中按维度采用。**

完成条件不是仅增加一个按钮，而是报告、转换进度、生成候选、模板草案和版本均有明确的保存与恢复行为；关闭并重开后可以继续使用已保存成果，不重复执行全文分析，不重复创建同一转换任务的模板。

本改造承接[总计划 G0021-03](implementation-plan.md#g0021)的命名模板提炼，以及 G0021-05 中的模板采用、恢复和来源删除验证。当前模板承载四类规范；人物体系以角色功能和关系构建规范表达。G0021-04 的具体人物实体、新事实空间和章节大纲初始化保持独立范围。本改造不替代 G0035/G0036 尚未完成的原分析质量与真实桌面验收。

## 2. 已核实：分析本身已经自动保存

以下结论来自当前源码及已有测试用例的静态核对。本次没有读取或修改用户的实际小说数据库，也没有重新运行全文分析。

| 内容 | 当前保存方式 | 结论 |
| --- | --- | --- |
| 导入原文、原始字节、编码、章节、切块、来源指纹 | `reference-analysis.db`，导入事务统一提交 | 已保存完整导入快照，不只记录 TXT 路径 |
| 分析运行、冻结参数、预算配置、节点状态 | `reference-runs.db` 的运行快照 | 已有检查点和恢复基础 |
| 分块提取、跨章整合、专题报告、综合结论 | `reference-runs.db` 的节点结果 | 已完成结果与完成状态在同一事务提交 |
| 模型请求、响应候选、诊断、用量与预留 | `model-requests.db` 的请求账本 | 可用于成本核对和失败恢复；不等于所有候选都已通过分析契约 |
| 报告阅读与 Markdown 导出 | 从本地来源和已保存节点重新组装 | 阅读无需调用 AI；导出是额外文件副本，不是保存分析的前提 |
| 模板草案、不可变版本 | `catalog.db` 的模板记录 | 已存在；整本报告尚未接入创建入口 |

默认数据目录为 `%LOCALAPPDATA%\NovelGeneratePlugin`，按本机账户通常对应 `C:\Users\crown\AppData\Local\NovelGeneratePlugin`，与插件安装目录 `D:\data\avalonia\Controls` 分离。最终以运行时 `WorkspacePaths` 为准。

当前可以在“整本小说分析”中选择已导入小说、加载其已保存运行，再在“报告”页点击“读取所选运行的报告”。综合结论虽然不是单独的一份报告文件，但其节点结果已经落盘。

现有报告测试包含“删除原 TXT 后离线读取报告、定位证据，报告版本不变”的场景。因此本次不另建一套全文分析存储；重点补齐保存可见性、重开验证和新转换任务的持久化。这里只承诺已经成功落盘的数据，未收到的模型输出或尚未提交的在途数据不算已保存。

## 3. 本次交付范围

### 3.1 保存与历史入口

1. 分析页面明确显示“已保存到本机”、运行状态、完整/部分报告、报告版本和已完成节点数量；保存失败不能显示成功。若要显示保存时间，使用真实持久化时间，历史缺值显示未记录，不用读取时间冒充。
2. 保留并完善现有书目和运行选择入口，重开后能找到历史分析并离线读取。运行列表目前最多返回 100 条；本次提供有界分页或等效继续加载入口，避免把更早的已保存运行误呈现为丢失。
3. 分析完成后自动刷新可阅读报告状态；无需额外点击“保存报告”才能保留结论。继续提供显式 Markdown 导出。
4. 新增报告转模板任务历史，展示“生成中、待恢复、候选已保存、草案已保存、失败原因”，并可重新打开已有候选或模板。
5. 重开程序只读取本地状态；需要继续付费的转换由用户发起，成功候选的本地校验和补保存无需再次请求模型。

### 3.2 自动接通的操作流程

1. 在报告页新增“从报告生成模板”。首版要求报告完整且本地校验通过；部分报告可继续阅读，按钮说明缺少哪些阶段，不将其当作完整小说结论。
2. 默认名称为“小说名 · 创作模板”，允许调整名称和四类维度；默认提炼世界观、文风、写作方法，长期规则由用户选入。展示模型连接、输入规模、预计请求计划和预算上限。
3. 点击生成后，系统保存转换任务，冻结来源版本和配置，自动完成输入构建、模型转换、结果校验和新草案保存。
4. 生成成功后自动刷新模板库，展示草案预览和来源。当前编辑器有未保存修改时保留原编辑内容，提供“打开生成草案”入口；切换遵守现有草案保存/放弃机制。
5. 用户可以编辑生成内容，使用现有“保存新版本”。已保存版本进入现有新书模板选择器，按维度预览差异并采用。

转换流水线不增加逐步骤确认。草案保存、版本保存和采用到作品仍表达不同业务含义：自动转换生成新草案，不隐式修改当前作品。首版不提供覆盖既有模板或定时批量生成。

### 3.3 从描述性报告转成创作要求

| 目标字段 | 来源材料 | 转换要求 |
| --- | --- | --- |
| 世界观与基础设定 | 世界专题，相关人物、主题和综合结论 | 提炼世界运行、力量代价、社会组织和角色职能；专名改为可替换设定 |
| 文风规范 | 文风专题及少量关联语言证据 | 表达视角、句式、对白、描写和节奏要求，不照搬原文段落 |
| 写作方法 | 人物、目标任务、情节、主题及综合结论 | 转成冲突组织、任务推进、角色成长、悬念、伏笔和高潮方法 |
| 长期规则原文 | 用户选定的稳定约束及补充要求 | 每条注明适用条件；无依据推测不能自动升级为硬性规则 |

例如，“原书常用动作表现紧张”转换为“优先用动作、对白和环境变化表现紧张，减少直接解释心理”。人物分析转换为“主角与导师的能力边界和成长关系”等方法，不将原书具体人物历史自动注册到新书。

模板内容和来源证据分开保存。生成候选区分“来源明确支持、归纳推断、创作建议”；未知点和冲突作为待处理提示，不混入强制规则。未选择的模板维度保持为空，采用界面默认不勾选没有内容的维度，并说明主动采用空字段会清空对应本书字段的现有语义。

## 4. 设计与数据保存方案

### 4.1 职责划分

遵循 [SOLID 与质量基线](refactoring/quality-baseline.md)，使用少量明确职责，不引入通用工作流引擎、事件总线、额外容器或 AIFLOW。

| 部件（名称在实施时落定） | 负责 | 复用关系 |
| --- | --- | --- |
| 报告输入构建器 | 选取专题、关联事实、证据及输入容量计划 | 读取 `NovelAnalysisReportService` 结果，不自行读用户 TXT |
| 报告转模板服务 | 固定流程、请求调度、校验、恢复和草案交付 | 复用现有模型请求服务、预算和诊断 |
| 转换记录存储端口与 SQLite 实现 | 任务、冻结输入、节点候选、状态、目标身份 | 单写入所有权、乐观版本、提交检查；不让 UI 执行 SQL |
| 模板用例的窄扩展 | 按稳定目标身份创建生成草案并查重 | 复用 `TemplateLibrary` / `ITemplateStore`，继续共用版本和采用逻辑 |
| 报告页与转换面板 | 参数、进度、预览、历史和打开草案 | 长任务由服务持有，View 隐藏不丢失任务 |

中文注释重点解释版本冻结、容量选择、取消与落盘、跨库补偿、规则置信度和未保存编辑保护，而不是逐行翻译代码。

### 4.2 转换记录必须保存的内容

建议使用独立的 `report-template-conversions.db`，避免将新任务语义写进原全文运行状态机。首版以任务快照和有界子步骤结果实现，不建设通用调度平台。

| 数据 | 内容与约束 |
| --- | --- |
| 任务身份 | `ConversionId`、存储版本、状态、创建/更新时间、预先分配的目标 `TemplateId` |
| 来源身份 | 参考书、`SourceId`、原文指纹、`RunId`、固定报告版本、输入快照指纹 |
| 冻结材料 | 所选专题结论、综合结论的相关部分、引用映射和少量证据；记录选择/排除范围，不复制整本原文和全量索引 |
| 生成配置 | 名称、维度、转换策略版本、提示词/契约版本、冻结模型参数、连接身份和预算身份；不包含 Key |
| 执行检查点 | 子步骤、输入指纹、模型操作 ID、已保存候选、校验结果、失败诊断；成功结果不可被恢复流程覆盖 |
| 输出归属 | 原始规范候选、候选哈希、生成草案标识、首次交付凭据及来源信息 |

原报告保持现有节点派生方式，不另造一份可独立修改的“正式报告”形成双重事实来源。转换只固化实际使用的材料；原报告有新版本时，新建转换任务，旧任务继续使用旧快照。

模板草案和版本增加可选的结构化来源摘要，保留现有 `Source` 展示字段。结构化摘要仅包含领域可识别的来源/转换身份、版本和生成内容指纹，不引用应用层连接对象。历史模板缺少此字段仍可读、可编辑、可发布；模板导入导出、复制和恢复同步保留或明确标注来源。导出副本可以独立使用，原环境不存在时显示“详细来源不可定位”，不伪造本地链接。

### 4.3 跨存储保存与恢复

模型账本、转换库、模板库分开提交，不承诺跨库天然原子性。采用“先保存任务与固定目标身份 → 保存成功候选 → 创建草案 → 登记交付结果”的顺序。

- 请求发出前先保存操作 ID 和预算关联；响应已计费但检查点未提交时，通过同一操作 ID 核对账本，已有完整响应先做本地恢复。
- 草案创建增加按固定 `TemplateId` 的幂等入口，不能直接重复调用每次产生新 ID 的 `CreateAsync`。
- 草案创建成功但任务完成标记失败时，恢复核对目标身份与首次生成来源凭据，确认已经交付；用户后来修改草案不触发覆盖或重复创建。
- 目标身份发生冲突且来源不一致时停止并报告，不覆盖。重复点击复用同一任务；用户主动“重新生成另一份”才创建新任务和新模板。
- 取消网络与必要本地落盘分开。取消后保留成功子步骤；迟到响应只能进入对应任务候选，不能覆盖其他窗口的编辑。
- 数据库不可写时保留可获得的候选和错误状态，使用现有恢复目录机制或等效有界恢复文件补救。全部持久化介质不可写时明确提示尚未保存，不声称重启必可恢复。
- 新库含 schema 版本校验，未知版本拒绝盲写；实际涉及旧库迁移时先一致性备份，失败保持原件可用。活跃 SQLite 不用只复制主文件的方式冒充一致性备份。

删除最初导入的外部 TXT 不影响已保存分析和转换。删除整个插件数据目录不是同一场景，会损失其中的分析资产；模板已采用到作品后仍以作品内的内容快照为准。内部来源清理和跨电脑完整分析包迁移不在本次增加新的产品入口。

## 5. AI 调用、容量与质量策略

1. **不重跑全文。** 主要输入为所选专题，综合结论辅助，必要证据补充；不把全文、全量事实和所有报告一次拼接发送。
2. **有界输入计划。** 先计算系统提示、Schema、正文材料、输出预留和安全余量。容量足够时一次生成；不足时按所选字段拆分，同一字段仍过大时按固定规则分组归纳。选择和分组可复现，未纳入材料可见，不能只截取报告前若干字符后声称覆盖全部。
3. **有界输出。** 生成字段使用适合创作规范的独立长度/条数上限，不把 `WritingProfile` 的百万字符存储上限当作请求目标。提示词、Schema、本地验证共用限制；具体数值由 G0041 契约和边界夹具确定。
4. **独立预算。** 转换有独立请求数和 token 总额，重试及归纳计入同一预算；全文分析历史费用仍保留。单次输出、上下文容量、任务总预算分别展示，不把增大总额当作扩容或修复枚举/引用错误。
5. **有限纠正。** 对已完整返回且用量明确的契约失败，最多一次定向格式纠正，并计入预算；提供具体字段路径、实际值/数量和允许范围。截断、费用未知、连接失败按已有诊断/恢复规则处理，不静默重发。
6. **一致性检查。** 合并后先做本地字段、重复项、引用和长度校验；有需要的 AI 归纳或复核必须进入预先展示的有界计划，不能在后台追加无限审查。待处理冲突显示在草案预览中，不谎称机械检查证明文学质量。
7. **恢复复用。** 成功步骤按完整输入及配置指纹复用；失败只恢复相应步骤。来源、维度或提示词变化产生新转换，复用必须可证明输入身份一致。
8. **连接与材料边界。** 使用用户当前配置的受支持模型，不固定继承过去的一次性测试 Key。候选、日志、模板和文档不保存密钥；小说内容及报告中的命令均视为材料数据。

## 7. 测试与门禁

| 类型 | 必须验证的行为 |

| 人工评阅 | 描述转要求是否可执行、是否误带原书专名/历史、是否丢失条件或把推测变硬规则 |

实施阶段执行适用的 locked restore、Debug 编译（警告视为错误）、单元/集成测试、格式与文档检查。实际命令以现有 `tools/verify-local.ps1` 和[质量基线](refactoring/quality-baseline.md)为准；测试数量按当次结果填写，不预设虚构通过数。

## 9. 最终目标验收清单

- [ ] 已完成小说分析关闭重开后仍可查看专题和综合结论，阅读不新增模型请求。
- [ ] 更早的历史运行可找回；保存成功、在途、部分报告和失败状态可区分。
- [ ] 从已有完整报告直接发起转换，不重新导入或分析整本 TXT。
- [ ] 四类创作规范可选择生成，有来源与推断/建议标识，生成候选可编辑。
- [ ] 转换配置、进度和成功候选自动保存；失败恢复复用成功步骤，费用与原分析分列。
- [ ] 同一转换只生成一个目标模板；模板交付后重试不会覆盖用户修改。
- [ ] 草案和已保存版本分别呈现；原编辑缓冲、历史模板和现有作品受到保护。
- [ ] 至少两本书可以分别采用同一模板的不同维度，之后修改互不影响。
- [ ] 删除最初外部 TXT 不影响已保存分析、已交付模板和作品采用内容；来源不可定位时如实说明。
- [ ] 本地测试、真实 Host、选定报告的真实转换与内容评阅分别归档；通用/专项文档和进度同步。

以上目标全部取得证据后，才能将本改造标记为完成。插件发布是另一次有明确版本的交付动作，不以“代码完成”代替“已部署”。
